# Hydration

After the server generates static HTML, the browser attaches event listeners and reactive Cells to make the page interactive. This process is called **hydration**.

## Basic Setup

In the client-side entry point, `hydrate` is imported from `retend-server/client` and passed the router factory function:

```tsx
// source/main.ts
import { hydrate } from 'retend-server/client';
import { createRouter } from './router';

hydrate(createRouter);
```

The `hydrate` function performs the following steps:

1. Finds the existing server-rendered HTML.
2. Re-creates the router and matches the current URL.
3. Attaches event listeners and reactive bindings to the existing elements.
4. Dispatches a `hydrationcompleted` event on `window` when finished.

```tsx
window.addEventListener('hydrationcompleted', () => {
  console.log('App is now interactive!');
});
```

## Options

The `hydrate` function accepts an options object as its second argument:

```tsx
hydrate(createRouter, {
  rootId: 'app',
  wrap(root) {
    return root;
  },
});
```

| Option   | Default | Description                                                                        |
| -------- | ------- | ---------------------------------------------------------------------------------- |
| `rootId` | `"app"` | The `id` of the root element that holds the server-rendered HTML.                  |
| `wrap`   | —       | A function that wraps the app root before rendering. Used to add global providers. |

### Wrapping the App

If an app needs a global provider (like a theme or auth context) that wraps the entire router, the `wrap` option provides it:

```tsx
import { ThemeScope } from './scopes';

hydrate(createRouter, {
  wrap(root) {
    return <ThemeScope.Provider value="dark">{root}</ThemeScope.Provider>;
  },
});
```

## Hydration Contract

`hydrate` uses the browser's current path, query, and hash as the initial router location. It hydrates roots marked with `data-retend-hydration="1"`; otherwise, it replaces the root contents with a client render.

Server and client structure must match. A structural mismatch rejects hydration; Retend does not recover individual nodes. Differing text and `dangerouslySetInnerHTML` values are updated on the claimed node. Once a dynamic range is claimed, normal reactive updates may run while other async boundaries are still hydrating.
